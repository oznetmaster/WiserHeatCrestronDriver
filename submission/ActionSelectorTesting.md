# Day and time action-selector testing

Crestron's extension form, Device Control item 17, requires each supported action to be selected, as well as checking the dialog and cancellation. Reading a list and selecting one sample does not establish all actions. These fixtures exercise unsaved editor selections; they do not write a hub schedule.

Select `WiserHeatCrestronDriver.AndroidTests.GatewayUiTests.ScheduleEditorEveryChoiceAppliesAndCancels(slot, requirePeer)` by its exact discovered case name. Slot `0` selects every weekday. Slots `1` through `8` select all 48 half-hour time choices in that row. The actual NUnit names use `False` or `True`, for example `ScheduleEditorEveryChoiceAppliesAndCancels(1,True)`.

Provide one explicitly bound `ControlRooms`/`Rooms` pair and private hub settings in the normal reserved installed-test workflow. Use Celsius editor settings. Run each time-row case with a schedule layout in which that row exists; an absent row is skipped and cannot satisfy a required-test gate. Do not confuse those skips with verified non-applicability. The current hub supports up to eight events; defensive slots nine and ten remain a separate absence/regression scope.

For `True`, additionally enable `ObservePeerDuringPendingEdits` and bind the verified second candidate and matching physical room as described in [two-instance testing](TwoInstanceTesting.md). Each choice then receives a fresh peer observation. For single-instance evidence use `False` with peer observation disabled. Reverse-direction evidence requires independently verified bindings.

Each sequence selects every value, including its initial value, restores the initial selection, and cancels. It checks the driver property and labelled rendered value after each choice. Time changes must preserve every other editor field. Day changes must load the matching saved day. Independent hub comparisons check all persistent schedules and guarded room settings after each action. Final cleanup verifies the original editor, schedules, room policy and Home. Failed or uncertain input is never repeated. On an uncertain day selection, restoration accepts only the original or immediately preceding/intended owned day; an unrelated selection blocks automatic recovery.

The bounded selector search handles a preserved scroll position, complete visible rows and explicit ordered labels. Changed selections, unexpected/duplicate/missing labels, stationary scrolling or an exhausted search fail. No failed gesture is retried. Evidence retains captured choice dialogs, input intent, selected values, hub comparisons and selected-choice coverage. These are functional test records, not an independent timing attestation: the final reviewed form bindings still need the appropriate trigger/response measurements.

These cases build and have offline search/isolation coverage. All 18 cases were discovered and refused to access hardware without the reserved workflow context. They have not yet run on the processors. Complete-list inventory, cancellation without a selection, schedule-assignment selectors, other editor controls, different layouts and the second rendered app retain their separate requirements; these new cases do not make the entire official item pass by themselves.

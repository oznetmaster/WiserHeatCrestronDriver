# Day and time selector-button testing

The day, time and schedule controls use SDK `selectorbutton` elements. They belong under Device Control item 9 (selector buttons), with applicable subpage and multiple-instance checks under items 18 and 19. Crestron's [UI definition documentation](https://sdkcon78221.crestron.com/sdk/Crestron_Certified_Drivers_SDK/Content/Topics/Driver-SDK-V1/Create-a-Driver/Device-Types/Extensions/UI-Files.htm) distinguishes these property-value controls from `actionselector` alerts, which have a title, action buttons and a fixed Cancel button. Item 17 concerns those alerts; it must not be inferred merely because a selector button opens a selection page.

The frozen 1.3.11 package contains twelve selector buttons in its room UI, no action-selector elements, and empty alerts sections in both UI definitions. Its package SHA-256 is `b84375d629ac5af2f65c1f6cde4dabf74a6302ff100caafd65d157ac1e6ab3cf`. The draft therefore proposes absence review for item 17. Packaged XML alone does not complete that review: retain runtime/configuration observations and verify that no additional action-selector alert is supplied. Existing pinned policies and collected evidence are not rewritten by this draft correction.

These fixtures exercise unsaved editor selections; they do not write a hub schedule. The full-value matrix and dismissal checks provide detailed functional coverage of item 9 and editor isolation. They are not a separate requirement to operate every value as an item-17 action. The historical filename is retained for existing links.

Select `WiserHeatCrestronDriver.AndroidTests.GatewayUiTests.ScheduleEditorEveryChoiceAppliesAndCancels(slot, requirePeer)` by its exact discovered case name. Slot `0` selects every weekday. Slots `1` through `8` select all 48 half-hour time choices in that row. The actual NUnit names use `False` or `True`, for example `ScheduleEditorEveryChoiceAppliesAndCancels(1,True)`.

Provide one explicitly bound `ControlRooms`/`Rooms` pair and private hub settings in the normal reserved installed-test workflow. Use Celsius editor settings. Run each time-row case with a schedule layout in which that row exists; an absent row is skipped and cannot satisfy a required-test gate. Do not confuse those skips with verified non-applicability. The current hub supports up to eight events; defensive slots nine and ten remain a separate absence/regression scope.

For `True`, additionally enable `ObservePeerDuringPendingEdits` and bind the verified second candidate and matching physical room as described in [two-instance testing](TwoInstanceTesting.md). Each choice then receives a fresh peer observation. For single-instance evidence use `False` with peer observation disabled. Reverse-direction evidence requires independently verified bindings.

Each sequence first opens that selector and uses its own toolbar Back control to dismiss it without choosing a value. It verifies unchanged editor properties, command activity, persistent hub schedules and guarded room settings; peer cases also require a fresh unchanged peer observation. This is the observed app dismissal control, not the background editor page's Cancel button. The sequence then selects every value, including its initial value, restores the initial selection, and cancels the editor page. It checks the driver property and labelled rendered value after each choice. Time changes must preserve every other editor field. Day changes must load the matching saved day. Independent hub comparisons check all persistent schedules and guarded room settings after each action. Final cleanup verifies the original editor, schedules, room policy and Home. Failed or uncertain input is never repeated. On an uncertain day selection, restoration accepts only the original or immediately preceding/intended owned day; an unrelated selection blocks automatic recovery.

The bounded selector search handles a preserved scroll position, complete visible rows and explicit ordered labels. Changed selections, unexpected/duplicate/missing labels, stationary scrolling or an exhausted search fail. No failed gesture is retried. Evidence retains captured choice dialogs, input intent, selected values, hub comparisons and selected-choice coverage. These are functional test records, not an independent timing attestation: the final reviewed form bindings still need the appropriate trigger/response measurements.

These cases build and have offline search/isolation coverage. All 18 cases were discovered and refused to access hardware without the reserved workflow context. They have not yet run on the processors. Schedule-assignment selectors, other editor controls, applicable layouts and paired-instance observations retain their separate coverage; these new cases do not make an entire official item pass by themselves.

The dismissal route is grounded in retained current-app hierarchies: the selection layer exposes `customdevice_selectionToolbar_backButton`, while the visible `Cancel` text belongs to the editor underneath. The observed selection toolbar title was empty. This is not, by itself, a violation of the separate action-selector title requirement. Check the selector button's own required label and observed usability under item 9. No physical dismissal acceptance is claimed until the updated sequence runs.
